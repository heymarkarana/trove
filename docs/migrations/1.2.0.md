# Migrating to Trove 1.2.0 — Always-On Verbose File Logging

## What changed & why

Before 1.2.0, Trove logged only to the terminal (stderr), filtered by
`TROVE_LOG_LEVEL`. `TRACE`/`DEBUG` detail and any command output suppressed by
`trove_silent_run` were lost. 1.2.0 adds a **second, independent file sink** that
**always** writes a plain-text, timestamped, secret-scrubbed log at full `TRACE`
verbosity — so a human or an LLM can be pointed at a complete trace to troubleshoot.

Logging is **per application**: an app selects a channel with `TROVE_LOG_APP` and
(optionally) a location with `TROVE_LOG_DIR`. Files are **per-actor** —
`‹dir›/‹app›-‹user›-YYYY-MM-DD.log`, mode `600`, owned by the writer — so nothing is
shared or leaked across users, including root/cron write-on-behalf. Retention keeps
the last 7 days by default.

This is a **minor** release: existing terminal behavior and every existing public
function contract are preserved. The items below are the only behavior changes.

## Breaking / behavioral changes

1. **New side effect: files are written by default.** With `TROVE_FILE_LOGGING=true`
   (default), any `trove_*` / `klog` call now also writes to a log file under
   `${XDG_STATE_HOME:-~/.local/state}/trove/logs/‹app›/` (or `/var/log/trove/‹app›`
   as root). Sourcing Trove alone writes nothing — only actual log calls do. To opt
   out entirely, set `TROVE_FILE_LOGGING=false`.

2. **`trove_silent_run` with `TROVE_OUTPUT_DISPLAY=false` no longer discards output.**
   Previously the command's stdout+stderr went to `/dev/null`; now they are **captured
   to the log file** (still shown nowhere on the terminal). Display-on behaviour is
   unchanged (native, live, separated streams). If a caller relied on output being
   truly discarded (e.g. secrets), note the scrubber runs, but prefer not logging
   secrets at all.

3. **`TROVE_ENABLE_LOGGING=false` now silences only the terminal.** The file sink is
   independent and keeps recording (that is the point of an always-on audit log). Use
   `TROVE_FILE_LOGGING=false` to stop the file too.

4. **New reserved env vars.** `TROVE_FILE_LOGGING`, `TROVE_LOG_APP`, `TROVE_LOG_DIR`,
   `TROVE_LOG_FILE_LEVEL`, `TROVE_LOG_RETENTION_DAYS`, `TROVE_LOG_FORMAT`,
   `TROVE_LOG_SCRUB`, `TROVE_LOG_SCRUB_PATTERNS`, `TROVE_LOG_CAPTURE_TEE`. If your app
   already uses any of these names for something else, rename yours.

5. **Requires zsh ≥ 5.3** for the file sink (`zsh/datetime`, `zsh/system`,
   `${sysparams[procsubstpid]}`). Trove already targets modern zsh (5.9 on current
   macOS); older zsh degrades gracefully (timestamps fall back to `date`; capture
   falls back to a raw synchronous redirect).

## Human checklist (per downstream app: dotFiles, Beskar, …)

- [ ] Pick a channel name and set `export TROVE_LOG_APP="<yourapp>"` in the app's env
      or config (once, early — e.g. in your bootstrap).
- [ ] Decide where logs live. Default (per-user XDG) needs nothing. For a fixed or
      system location, set `TROVE_LOG_DIR` (e.g. `/var/log/<yourapp>`) and ensure the
      directory is creatable/writable by the users/cron that will log. Run
      `klog --app <yourapp> init` to pre-create it and print the paths.
- [ ] Record the log path in your app's own config/docs so operators (and agents)
      know where to look: `klog --app <yourapp> path`.
- [ ] If your app suppressed command output via `TROVE_OUTPUT_DISPLAY=false` and
      assumed it was discarded, confirm nothing sensitive now lands in the file
      (the scrubber helps, but don't log secrets).
- [ ] To capture git / git-crypt activity, route git through `trove_git` (from
      `trove_load helpers`) or wrap the region in `trove_log_capture_begin/end`.
      **Never** log git-crypt-decrypted content.
- [ ] For fully-dormant or shared-directory channels, add a periodic
      `klog --app <yourapp> prune` (cron) so retention still runs.
- [ ] Verify: `TROVE_LOG_APP=<yourapp> klog INFO "smoke"; klog --app <yourapp> tail`.
