CLI Output Standard · draft for review

A visual language
for the command line

Color, weight, and structure aren't decoration — they're how a terminal communicates subtle organization and consistency at a glance. This distills the system already living in dotFiles into one generic standard, so every CLI — dotFiles, Beskar, Trove, and whatever's next — reads as one family.

Theme-agnostic: roles, not raw codes Built on Trove COL_* Reference theme: Monokai

The Palette

Eight semantic roles. Code never names a color for how it looks — it names it for what it means, so the same source renders correctly under Monokai, Nord, Gruvbox, or any Trove theme. Swatches show the Monokai reference values.

Glyphs

A fixed vocabulary, each locked to a role's color. Shape carries meaning even where color can't (pipes, colorblind readers, NO_COLOR).

✔Success / match green — the affirmative
✖Error / failure red
⚠Warning yellow
·Neutral bullet / no-match gray
➤Result / action taken trove_ok
✪Interactive / prompt trove_bot
●Status dot green / yellow / red — up · degraded · down

Weight & Style

Color is the primary channel; SGR attributes are the second. Use what the line needs — not all of them, every time. Reach down this list as emphasis escalates.

BoldPrimary emphasis — versions, the matched value, a key figure. The everyday second channel.
DimA softer mute than gray for inline secondary text. SGR 2 — check your terminal renders it
ItalicOptional annotation / captions. SGR 3 — inconsistent support; never load-bearing
UnderlineActionable paths & URLs, or the live heading. SGR 4 — sparingly
ReverseReserved for max severity — a status bar, a selected row, a blocking alert. SGR 7 — rare by design

Structure

Inline is the default — dotFiles and Beskar both use it throughout. Reach for the ruled form only when a screen is so dense that inline titles don't separate the groups clearly enough. Both put the title in the Header role.

A · Inline header — status & info

status
Paths
  install     /opt/dotFiles_data
  config      /opt/dotFiles_data/.config
  beskar      /opt/beskar

Title, then an aligned key/value block. The default for dashboards.

B · Ruled header — dense help

help
────────────────────────────
 CONFIGURATION
────────────────────────────
  config       Show config
  config init  Initialize it

Rule, title, rule — the exception, for exceptionally dense help.

The one rule that's easy to miss

A ruled heading gets exactly one leading space before the word — CONFIGURATION, not CONFIGURATION flush to the margin. That single space lifts the title off the rule and reads as a deliberate label instead of a run-on. It's the difference between ───/word/─── looking typeset versus accidental.

Commands & References

Beyond the header/value block, two row shapes — both keep the command in the Key role, and differ in how the right side reads.

Full command → # comment

copy-pasteable
beskar config     # Show current config
dotFiles up trove # Update only Trove

A runnable command gets its description as a muted # comment — the whole line pastes as valid shell.

Bare token → plain description

reference
Commands:
  on               Enable the trailer
  --setup          Create the symlink
  issue [domain]   Issue a cert

A subcommand name, flag, or arg placeholder isn't runnable on its own — plain aligned text, no #.

Source references — first-class

beskar help config
Library:
  lib/beskar_config_commands.zsh — beskar_config_init, validate, edit, show
  lib/beskar_config.zsh          — beskar_load_config, beskar_validate_config, …

A Library: / Registry: / Resolver: pointer (file → its key functions) is a full section: Header label, Key paths, plain functions, an em-dash (a definition, not a command — so no #), aligned down the block.

Applied · Beskar help

Same content, brought into the standard. Uppercase-plain headings become inline Header titles; the ==== slab and ━━━ rules are dropped; command names take the Key role with descriptions as # comments; the Library: pointer gets first-class weight. Channels

Where output goes matters as much as how it looks.

  • Status, progress, errors → the trove_* loggers → stderr. They apply the role color and glyph for you. Never hand-roll status with raw echo.
  • Structured, tabular & help text → echo/printf with COL_* → stdout. This is the only place you write color yourself.
  • --json / --porcelain → zero color, ever. Machine output must stay byte-stable. Beskar already gates this — codify it everywhere.
  • Honor NO_COLOR and non-TTY. When stdout isn't a terminal, degrade to plain text; glyph shapes still carry meaning.

Integrating Color

Two things bite when you wire this into a CLI — how the escapes are stored, and how a theme gets chosen.

COL_* are literal strings

materialize
# echo / printf-format interpret them:
printf "${COL_CYAN}%s${COL_RESET}\n" "$k"

# print -r does NOT (emits \033 literally):
c=$(print -- "$COL_CYAN")   # once
print -r -- "${c}${path}${rst}"

COL_* hold literal \033[…] text; a raw print -r won't interpret it. Materialize to real bytes first.

Selecting a theme

colorscheme
# bridge your env var → Trove, at startup
: ${BESKAR_COLOR_SCHEME:=monokai}
trove_set_colorscheme "$BESKAR_COLOR_SCHEME"

Reference roles, never hex — so every theme just works. dotFiles bridges DF_COLOR_SCHEME, Beskar BESKAR_COLOR_SCHEME.

Conformance Checklist

Run any CLI against this. Each item is mechanical — pass or fail.

  • Section titles use COL_BOLD_PURPLE, not plain uppercase.
  • Keys/labels use COL_CYAN, aligned in a fixed-width column (%-Ns).
  • Ruled headings have exactly one leading space before the word.
  • Success / warning / error use green / yellow / red and the matching glyph.
  • Metadata, timestamps & separators use COL_GRAY.
  • Full-command rows carry a muted # comment description; bare-token rows use plain text.
  • Library:/Registry:/Resolver: pointers: Header label, cyan paths, plain functions, aligned —.
  • COL_* materialized before a raw print -r; theme set via trove_set_colorscheme.
  • No raw echo for status — trove_* loggers only.
  • Color sits in an echo string or printf format position — never a %s argument.
  • Every colored span is closed with COL_RESET.
  • Colors referenced by role via COL_* — never a hardcoded \033[…] literal.
  • --json/--porcelain emit no escape codes.
